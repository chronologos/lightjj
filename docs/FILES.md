# File Guide

Per-file map of the codebase: what each file does plus the invariants, gotchas, and design notes that matter when changing it. The compact one-line-per-file index lives in [CLAUDE.md](../CLAUDE.md#project-structure); this is the detailed version. Read a file's entry before modifying the file or adding a new caller of its exports; update the entry when adding, removing, or renaming a file or when its contract changes (and keep the CLAUDE.md one-liner in sync). Test files get entries only when the test setup itself carries invariants worth noting.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the system-level design these files implement.

## cmd/lightjj/

- **`main.go`** — CLI entry point, flag parsing, embeds frontend-dist/. Startup order matters for persistence: MigrateConfigIfNeeded → MigrateStateIfNeeded → tab restore (ReadPersistedTabs) — the state migration must run before tab restore or upgraded users lose their tabs on first launch. `resolvedVersion()` is the ONE binary-version source (ldflags `main.version` → module build info → "dev"); the session file's `version` stamp reuses it. Owns the `sessionWriter` wiring: initial `Update()` after the restore loop (so tab 0 + restored tabs are in the first snapshot), `tm.OnTabsChange = session.Update`, `session.Remove()` on shutdown. `--allowed-host` (repeatable/comma-separated `hostList` flag value — split only, no validation) → `api.NewHostPolicy` right after flag checks (invalid entry → stderr + exit 2), stderr no-auth WARNING after bind when non-empty, and `hostPolicy.Middleware(api.Gzip(tm.Mux))` as the outermost handler (replaced the old in-file `localhostOnly`).
- **`frontend_embed.go`** — `-tags embed` build: frontendHandler serves the go:embed'd frontend-dist/.
- **`frontend_stub.go`** — Default (no embed tag) build: frontendHandler returns a static "frontend not bundled" help page pointing at release binaries or a `-tags embed` source build, so plain `go install` binaries don't 404.
- **`session_file.go`** — Agent port-discovery: writes {pid,addr,port,repo_dir,mode,started_at,version,tabs:[{id,path}]} to `$XDG_RUNTIME_DIR/lightjj/sessions/<pid>.json` after bind and REWRITES it on every tab open/close; stale-pid sweep; symlink-race-hardened TempDir fallback (verifyOwnedDir double-check). No-op on Windows. Agents match their cwd against any tab path (repo_dir for pre-tabs files) instead of needing the random port. `writeSessionFile` is atomic (os.CreateTemp in the same dir → 0600, name not ending in .json so readers/sweep skip it → rename) because `lightjj api` may read mid-rewrite. `sessionWriter` is the lifetime owner main.go holds: identity fields fixed at construction, `Update()` re-invokes the tab-snapshot func INSIDE its mutex (concurrent open/close handler goroutines can't land a stale snapshot last), `Remove()` at shutdown; a failed write keeps the previous file+path. `readSessions` owns the 64 KiB per-file cap and normalizes absent `tabs` to `[]` (never nil — `sessions --json`). `sessionTabsOf` adapts `[]api.TabRef`; internal/api never learns about session files.
- **`session_file_unix.go`** — verifyOwner: checks the session dir is owned by the current uid (unix builds).
- **`session_file_other.go`** — verifyOwner no-op stub for non-unix builds (Windows short-circuits earlier in writeSessionFile).
- **`api_cmd.go`** — `lightjj api METHOD PATH [BODY]` + `lightjj sessions` subcommands: loopback-only HTTP client (validateAddr rejects non-localhost) with session-file discovery, for agent harnesses whose sandboxes denylist curl/wget. Discovery is per TAB path (`candidateTabs` — old files synthesize repo_dir as tab "0"; non-numeric ids dropped since the id is embedded in the URL), deepest tab within a session then deepest across sessions, same-path tie = error; `discoverSession` returns the matched `sessionTab`. Tab targeting: `resolveTabPath` prefixes a tab-relative `/api`/`/api/...` PATH with `/tab/{matched}` (safe — every root /api/* route is also tab-mounted; kills the SPA-HTML footgun), explicit `/tab/N/` and `--addr` paths are verbatim; a non-launch-tab match prints one stderr line (and flags an explicit `/tab/N/` that disagrees). `versionMismatchWarning` → one stderr line when the session's `version` ≠ `resolvedVersion()` (absent stamp = silent). `sessions` shows VERSION (`-` if absent) + extra-tab continuation rows; `--json` is the raw records. Security model + discovery algorithm in [design-notes/api-cli.md](design-notes/api-cli.md).
- **`skill_cmd.go`** — `lightjj skill [install]`: prints or installs the go:embed'd SKILL.md (the agent-facing guide to `lightjj api`); install refuses to overwrite a file that doesn't carry the lightjj marker unless `--force`.
- **`apply_hunks.go`** — `--apply-hunks=<spec.json>` re-entry path for `jj split --tool lightjj-hunks`: dumb writer applying the frontend-synthesized write/revert/delete spec into jj's $right dir, with path-escape checks. All hunk-patching logic lives in frontend hunk-apply.ts.

## internal/jj/

Command builders + data models (PURE — no I/O, no side effects)

- **`commands.go`** — Functions that return []string args for jj subcommands, plus the parsers for their template output. Two template/parser styles coexist: legacy delimiter-positional (`\x1F`/`\x1E`/`\x1D` + SplitN — LogGraph, OpLog, FilesBatch, ConflictList, …) and json()-composed (one JSON object per line, `encoding/json` parse — `OpLogJSON`/`ParseOpLogJSON`, the reference migration). NEW parsers must use the json() style (jj ≥ 0.31, `JSONTemplates` gate — see CLAUDE.md Go conventions); existing delimiter parsers migrate opportunistically. LogGraph's `_PREFIX:` block ends with `self.hidden()` (position 8; explicit `++ _PREFIX: ++` concat, NOT separate()) — see graph.go on why the glyph alone is insufficient.
- **`commit.go`** — Commit model with ChangePrefix/CommitPrefix, Immutable, Divergent, WorkingCopies, Mine, AuthorEmail, Timestamp
- **`bookmark.go`** — Bookmark model + output parsers; ParseBookmarkListOutput/ParseRemoteListOutput take defaultRemote param for sort order. `BookmarkRemote` carries per-ref `AuthorName`/`AuthorEmail` (tip-commit author — display + author-filter target), `CommitTs` (committer timestamp, epoch SECONDS — the "Recent" sort key; frontend derives the relative age from it), and `Mine` (`normal_target.mine()` — author is me; the UI suppresses the author label on your own branches). Template is 14 \x1F-fields (bookmarkListTemplate in commands.go); parser guards `len(parts) < 14`. No jj-version gate — author()/committer().timestamp().format("%s")/mine() are core template builtins.
- **`alias.go`** — jj config alias parser. Handles both the simple array form (`aliases.l = [...]`) and the table form (`aliases.s.definition = [...]` + `aliases.s.doc = "..."`, jj ≥ 0.42's documented `{ definition, doc }` shape) — sub-keys coalesce by name into one `Alias{Name, Command, Doc}`; entries that never yield a command are dropped (a stray `.doc` is ignored). `Doc` flows to the Command Palette hint. No jj-version gate — `jj config list` emits this format identically across versions; it's just config the user may or may not have written.
- **`file_change.go`** — FileChange model, FilesTemplate (single-call file stats + conflict info), ParseFilesTemplate
- **`file_list.go`** — Full tree at a revision (issue #39): `TreeFile{Path, Type, Executable}` + `FileListJSON` (json()-composed `{"path","type","executable"}` per line — `json(path)`, which is REPO-relative; never the default template's `format_path(path)`, which is cwd-relative and breaks in SSH mode/subdirs) / `FileList` (pre-json `path ++ "\n"` fallback: no type/executable, and a path containing a newline splits into two bogus entries — the only loss) / `ResolveCommitId` (pin a symbolic rev to its commit id before caching) + `ParseFileListJSON`/`ParseFileList` (empty slice never nil; ParseFileList is verbatim — no TrimSpace, spaces are legal in names). `jj file list -T` exists since 0.26; the JSON path is gated on `JSONTemplates` (0.31). Measured on jj 0.45.1: the extra file_type/executable fields cost nothing over bare `path`.
- **`divergence.go`** — DivergenceEntry, Divergence() template builder, ParseDivergence. committer_ts DELIBERATELY absent (structurally inverted for --at-op). splitNonEmpty helper.
- **`selected_revisions.go`** — Multi-revision selection helper
- **`version.go`** — Semver type + ParseSemver + named feature gates (WorkspaceRootTmpl, ChangedPathIndex, CommitIdRevsetFn, JSONTemplates — the latter moved here from commands.go when handleFileTree became its first handler) + `FeatureGates` wire registry (gate name → minimum Semver). GET /api/info resolves every registry entry through `Server.jjSupports` (pessimistic) and ships the booleans as `features` — the frontend reads those instead of keeping a version table, so this map is the single authority on minimum versions. Keys are a wire contract with frontend `jjSupports(name)`.
- **`workspace_store.go`** — Protobuf parser for .jj/repo/workspace_store/index (name→path map). <0.40 fallback — ≥0.40 uses WorkspaceRef.root() in the WorkspaceList template.
- **`workspace_store_test.go`** — Parser tests with real binary data

## internal/runner/

CommandRunner interface + implementations

- **`runner.go`** — Interface definition (Run, RunWithInput, RunForMutation, StreamCombined, RunRaw, WriteFile)
- **`local.go`** — LocalRunner: exec("jj", args) with configurable Binary. WriteFile does symlink-escape hardening (EvalSymlinks on parent + Lstat leaf) before os.WriteFile. ResolveWorkspaceRoot rejects forgotten workspaces: `jj workspace root` exits 0 inside a forgotten workspace's dir, so a `jj log -r @` probe (probeWorkspace) follows it — tab create 400s and the startup restore loop log-and-skips instead of mounting a permanently broken tab.
- **`ssh.go`** — SSHRunner: wraps jj args in ssh command. WriteFile pipes content via `cd <repo> && cat > <path>` over stdin — no symlink check (same trust boundary as remote shell).

## internal/api/

HTTP handlers

- **`server.go`** — Route registration, runMutation, op-id caching, workspace store reader, helpers. For pure decode→validate→build mutations the route line IS the handler (`reg("POST /api/new", mutation(s, newRequest.validate, newRequest.build))`); the endpoint table in docs/ARCHITECTURE.md is drift-checked by architecture_doc_test.go. `Server.OpenTabRoots` (func field, injected by TabManager.addLocked; nil in tests/standalone) reports all open tab roots for cross-tab guards. The op-id cache is encapsulated behind `getOpId()`/`setOpId()`/`casOpId()` — the `cachedOp`/`cachedMu` fields are an implementation detail nothing else (besides `refreshOpId`, which composes them with the actual jj read) should touch; the SSH poll loop's compare-and-swap goes through `casOpId`, never the mutex directly. `trySnapshot()` is the pause-respecting snapshot path used by snapshotLoop and handleFileWrite; handleSnapshot checks the pause inline instead because it needs runMutation's response envelope and runMutation itself bumps the pause counter.
- **`handlers.go`** — Endpoint implementations, flag validation, and `mutation[Req](s, validate, build)` — the generic decode→validate→build→runMutation factory. Pure mutations exist as request structs with `validate()`/`build()` method pairs (no named handler func); `opMutation`/`bookmarkMutation`/`bookmarkRevMutation`/`bookmarkRemoteMutation` are thin adapters over `mutation()` for families sharing one request shape. Hand-rolled handlers are the ones with extra behavior: stdin (describe), streaming (git push/fetch/alias/index-paths), runner-backed validation (alias), tempfiles (split-hunks, merge-resolve), non-400 guards (workspace forget), server-state builds (workspace add), description reads (squash `source`/`combine` modes read the involved descriptions via `composeSquashMessage` → `-m`, issue #22), post-mutation side effects (snapshot, file-write, unlock-repo). Every success response uses the MutationResult envelope `{output, warnings?}` (apiVersion 2 unified the legacy `{ok}`/`{status}` shapes). Workspace name validation is two-tier: `workspaceNameRe` (strict, ADD only — name becomes a dir suffix) vs `validateWorkspaceRefName` (loose, forget/rename — jj allows dots/slashes in existing names; flag injection blocked by the `--` in the command builders). `workspaceNameMutation(build, guard)` is the forget/rename factory (decode→validate→guard→runMutation; stays hand-rolled because guard returns non-400 statuses); `forgetOpenTabGuard` 409s when the target workspace's path (via `workspacePathMap`, shared with handleWorkspaces) matches any open tab root, and allows when the path can't be resolved. `handleWorkspaceUpdateStaleOther` (issue #21) recovers a SIBLING workspace by name: resolve its root via `workspacePathMap`, then run `jj -R <path> workspace update-stale` through **RunRaw** (NOT runMutation) — the runner injects the tab's own `-R RepoDir` and jj rejects two `--repository` flags, so RunRaw (which adds no `-R`) is the only way to target a sibling in both modes; path comes from jj's own output so it's never request-injected; 422 when the path is unknown (predates jj's workspace_store index). The current workspace keeps its watcher-cleared `handleWorkspaceUpdateStale`.
- **`handlers_test.go`** — Handler tests with MockRunner
- **`architecture_doc_test.go`** — Drift guard for the docs/ARCHITECTURE.md endpoint table: parses `| METHOD | \`/api/...\` |` rows and asserts two-way sync with `routes()` (every registered route documented, every documented `/api` row registered). Tab routes (`/tabs`, `/tab/{id}/*`) are exempt — they're TabManager's, not `routes()`'. Sibling of agent_docs_test.go (the agent_api.md guard).
- **`integration_test.go`** — Integration tests (build-tagged)
- **`watcher.go`** — fsnotify on .jj/repo/op_heads/heads/ + SSE push, periodic util snapshot. Internals are typed: broadcasts are `sseEvent{name, data, droppable}` values (constructors `opEvent`/`navEvent`/`pollFailEvent`, sentinel vars `evStaleWC`/`evFreshWC`/`evPollOk`) that map 1:1 onto the `event:`/`data:` wire frames — the names/payload shapes are the api.ts contract and must not change; `handleEvents` is a single formatted write with zero event-type dispatch. `broadcast()` drops `droppable` events (op-ids, nav hints) when a subscriber's buffer is full, but EVICTS the oldest queued event to deliver non-droppable sentinels (stale-wc/fresh-wc, pollfail/pollok) — they're edge-triggered and never re-sent, so a dropped one would stick the client until reconnect. Both background loops classify probe results through ONE shared `probeTracker` (`ok`/`staleWC`/`fail`): it owns the consecutive-error counter, the 3rd-then-every-12th log throttle, the `pollFailThreshold` UI gate, and the unconditional poll-fail-clear discipline (the stale-WC-interlude-leaves-pollFailed-stuck bug previously had to be fixed once per loop — the invariant comments now live once, on the struct). SSH mode uses `sshPollLoop` (`PollOpId` — implicit snapshot + op-id in one round trip; no remote deps; `Server.casOpId` CAS against the pre-poll cache value so a concurrent runMutation advance isn't regressed). `interval <= 0` disables both loops (parity). Stale-WC detection: `isStaleWCError()` → `setStale(bool)` (staleMu-serialized Swap+broadcast — handler clear can't race a loop set and emit sentinels out-of-order; Swap edges don't re-fire so the race has no self-heal) → `evStaleWC`/`evFreshWC` → frontend non-dismissable warning with "Update stale" action. Both handleSnapshot + handleWorkspaceUpdateStale call `clearStale()`. Snapshot-pause counters are shared per canonical repo path via the package-level `pauseCounterFor` registry, resolved at watcher CONSTRUCTION (`pauseKey`: RepoDir locally, RepoPath over SSH) — same-path tabs share one counter with no post-construction field swapping. `handleEvents` refreshes the op-id if the cache is empty (read-only session path), emits current stale + poll-fail state unconditionally on connect (both branches — false branch covers SSE-dropped-during-staleness → CLI-recovered → reconnect), per-write WriteDeadline extension (not blanket disable — dead TCP surfaces in ≤85s).
- **`watcher_test.go`** — Broadcaster tests (subscribe/broadcast, droppable-drop on full buffer, sentinel eviction on full buffer), sshPollLoop tests via seqRunner (hook field for mid-call injection), setStale edge-only invariant, handleEvents refresh-if-empty table, CAS-guards-concurrent-advance, stale-interlude-clears-pollfail on BOTH loops (the shared probeTracker discipline), shared-pause-counter-by-path
- **`tabs.go`** — TabManager: per-tab Server + Watcher mounted at /tab/{id}/; TabResolve + TabFactory injection (mode-agnostic validation via closure); openTabs persisted to **state.json** via `SetOpenTabs` (state.go — NOT config.json, so tab churn never runs the JSONC patch machinery; tab 0 excluded — fights with -R on next launch); startup restore re-runs resolve() so moved repos log-and-skip. Both handlers funnel their post-response side effects through `tabsChanged()` (persistTabs → then `OnTabsChange` if set). `OnTabsChange func()` + `TabRefs() []TabRef` (id+path, id order, tab 0 included, RLock snapshot) are the out-of-package hook cmd/lightjj's session file rides on — the callback deliberately carries NO snapshot (concurrent creates would deliver stale snapshots in either order; the listener re-snapshots under its own lock), startup `AddTab` does NOT fire it, set it before serving (plain field like Mode). `OpenTabRoots()` (RLock) returns every open tab's root; addLocked injects it into each mounted Server (feeds the workspace-forget cross-tab guard) and stamps `RepoRoot` (grouping key via `Server.repoRoot()`). `handleList` enriches per-response from in-memory Server state (`wsNameCached()`, `Watcher.Stale()`) — no subprocess on the request path so a hung tab runner can't block the list; `resolveWsNameAsync` (fired at addLocked) fills wsName off-path with its own timeout. Value copies so concurrent list requests are race-detector-clean. NewTabManager also registers the host-scoped config + state routes on its Mux. addLocked wires only the SSE subscriber hooks (idle shutdown); snapshot-pause sharing across same-path tabs is NOT wired here — watchers resolve their shared counter at construction (`pauseCounterFor`, watcher.go).
- **`config.go`** — Server-side JSONC config (tailscale/hujson) for HUMAN-edited keys only; mergeAndWriteConfig applies per-key RFC-6902 add patches so comments on existing keys survive; fresh installs (ENOENT) seed from configTemplate, corrupt files NEVER reseed — 422 + frontend warning keeps user's bad file untouched (ErrConfigUnparseable sentinel). Machine-written keys (openTabs, recentActions) live in state.json (state.go), never here. GET /api/config returns Standardized JSON (422 on corrupt); GET/POST /api/config/raw round-trips raw JSONC for ConfigModal (text/plain only, 1MB cap, originAllowed guard). `isLocalOrigin` is the loopback baseline of `HostPolicy.AllowsOrigin`; handlers call `originAllowed(r)`, never `isLocalOrigin` directly. Atomic writes go through the shared `atomicWriteFile` (jsonstore.go).
- **`config_jsonc.go`** — hujson helpers: standardizeJSONC (bytes.Clone first — hujson.Standardize mutates input via aliased Extra slices), unmarshalJSONC, patchConfigKeys, removeConfigKeys (RFC-6902 "remove"; only pass keys that exist — removing an absent path errors). The centralised "Standardize before Unmarshal" idiom — any new json.Unmarshal on config bytes must go through unmarshalJSONC or break the first time the user adds a comment.
- **`config_template.go`** — First-run JSONC template string (in-tree constant, not a file). Teaching comments over theme, fontSize, editorArgs, font families. Kept in sync with frontend defaults and [CONFIG.md](CONFIG.md) by convention — see the top-of-file comment.
- **`state.go`** — Machine-state store: state.json (plain JSON, NOT JSONC) next to config.json, holding values lightjj writes itself — `openTabs` (PersistedTab; SetOpenTabs filter-merges by (mode,host) so concurrent sessions don't stomp each other; ReadPersistedTabs for startup restore) and `recentActions` (namespace → key → ms timestamp; SetRecentActions whole-section replace). One `stateMu` over every read-modify-write; atomic writes via `atomicWriteFile`. Missing/zero-byte/corrupt files all read as fresh (machine state is recoverable; nothing to protect with a 422). `MigrateStateIfNeeded` (main.go startup, after MigrateConfigIfNeeded, before tab restore) imports legacy openTabs/recentActions from config.json then removes them via removeConfigKeys — import is written BEFORE removal so failure can't lose data. HTTP: GET/POST /api/state/recent-actions (package-level handlers, host-scoped like config; POST has the originAllowed guard).
- **`jsonstore.go`** — Generic `jsonCollection[T hasID]` keyed flat-file JSON-array store (key → one file via `pathFor`, items addressed by ID). Owns the machinery annotations + doc-comments previously hand-mirrored: per-collection read-modify-write mutex, merge-on-upsert (preserve-on-empty, runs BEFORE stamp so merge detects "client omitted X" by zero value), server-side `stamp` defaults, configurable `deleteMatch` (cascade), delete-file-when-last-item-removed, and `UpsertBatch` (whole batch under one lock). Collections MUST be package-level vars, not Server fields — store files are shared across tabs, so the mutex must be too. Errors are `storeError{status,msg}`; handlers map via `storeErrStatus` (bad key → 400, I/O → 500). Low-level readJSONStore/atomicWriteJSON live here too, plus `atomicWriteFile` — the SINGLE temp-file+rename primitive shared by jsonstore/config/state (it prevents torn writes only; lost-update prevention is the caller's mutex).
- **`annotations.go`** — Per-changeId review comments (annotations/{changeId}.json): `Annotation` type + `annotationStore` collection config (pathFor=annotationsPath with changeId regex validation; merge preserves resolution/resolvedAtCommitId AND legacy Status under the same condition, plus createdAt; stamp fills createdAt) + thin GET/POST/DELETE handlers. DELETE without id = clear-all (DeleteAll).
- **`doc_comments.go`** — Doc-mode range-anchored comments/suggestions: `DocComment`/`DocAnchor` types + `docCommentStore` collection config (key = RepoPath+"|"+cleanDocPath(filePath) via `docCommentKey`, filename = sha256(key)[:16]; merge preserves resolution/resolvedAt/createdAt; stamp fills randID + createdAt; deleteMatch cascades to replies via ParentId) + GET/POST/DELETE/batch handlers. cleanDocPath: ToSlash+Clean+strip ./, reject ../ and / (400). POST validates anchor.selection. DELETE requires id (no clear-all). Batch validates ALL comments before writing ANY (all-or-nothing via UpsertBatch).
- **`agent_docs.go`** — `GET /api/agent` serves go:embed agent_api.md (the agent-facing contract). agent_docs_test.go fetches it and asserts every /api/* path mentioned is a registered route — the structural guard against doc/route drift.
- **`symbol.go`** — rg-backed go-to-definition for `GET /api/symbol` (Tier 1 — heuristic, no language server): one `symbolLangs` table (key = frontend LANGUAGES name → rg `--type` list (unioned; svelte searches svelte+ts), optional `--type-add`, definition regex template, `commentSyntax`, optional `normalize`) covering go/ts/js/py/rust/swift/zig/protobuf/bash/svelte, run against the working copy via `rg --json` through RunRaw (so it works in SSH mode), capped hits. `name` is per-language normalized first (bash: `$FOO`/`${FOO…}` → `FOO`, since the hoverable shell token carries the sigil) then identifier-gated + QuoteMeta'd — normalize can only narrow. An entry is only reachable if the frontend highlighter classes that language's identifiers (data-sym spans). `trimDocComment` narrows each hit's raw `-B6` Context to the trailing contiguous run of comment (line-prefix or standalone `/* */` block) + decorator/attribute lines directly above the definition — blank or code line ends the run (a block comment trailing code on its line counts as code), no leading comment → `[]`, nil syntax → passthrough. Adding a language = one table entry (verify the rg type via `rg --type-list`).
- **`file_tree.go`** — `GET /api/file-tree?revision=&dir=` (one directory's children, dirs first then case-insensitive name, dirs carry a recursive `files` count; 404 when `dir` isn't a directory) and `GET /api/file-tree/search?revision=&q=&limit=` (ranked: basename prefix > basename substring > path substring > subsequence; whitespace-separated terms must all match; default 200 / max 1000 results + pre-limit `total`). Both are served from an immutable per-commit `fileTree` index built from ONE `jj file list` run — filesets can't enumerate a dir's immediate children, so per-dir jj calls would still walk the subtree. Hex commit ids are pinned with `commit_id()` (CommitIdRevsetFn); anything else (`@`, a bookmark) is resolved to a commit id FIRST (`ResolveCommitId`, ≠1 commit → 400), so the cache key is always content-addressed (never invalidated). `fileTreeCache` (Server field, per tab): LRU bounded by entry count (6) AND total files (600k; the newest entry always survives), in-flight dedup (concurrent requests share one jj run), load runs on a context DETACHED from the request (WithoutCancel + 2-min timeout) so a navigating-away leader can't fail its followers; errors are never cached. Caps (vars so tests can shrink them): 250k files per listing (`truncated`, lexicographic prefix kept), 20k entries per dir response (`omitted`). Measured: 200k-file synthetic repo → ~1.5–3s cold, <1ms warm per dir, ~10–25ms per search, ~135 MB server RSS with that one index loaded.
- **`focus.go`** — `GET/POST /api/focus`: frontend-reported "what is the user looking at" (change_id/commit_id/active view/doc path) for the agent steering loop. Server-stamped UpdatedAt, per-tab singleton (each tab is its own Server), field-length caps.
- **`open.go`** — Open-in-$EDITOR: buildEditorArgv ({file}/{line} substitution, argv[0] validation), handleOpenFile. Setsid via build-tagged detachProcess (open_unix.go / open_windows.go). The ONE sanctioned `exec.Command` outside internal/runner/ — the editor must spawn where lightjj runs (it opens a window on the user's machine), not where jj runs; routing through the runner would launch it on the SSH remote.
- **`open_unix.go`** — detachProcess via Setsid (!windows) so Ctrl+C on lightjj doesn't kill the spawned editor.
- **`open_windows.go`** — detachProcess no-op (windows builds).
- **`gzip.go`** — Gzip response middleware (lazy-init writer, Flush passthrough for SSE)
- **`hostgate.go`** — `HostPolicy`: the single "which hostnames may address this server" answer. `Middleware` (outermost handler, main.go) 403s a disallowed `Host` (DNS-rebinding defense; loopback baseline is the exact pre-#45 `localhost`/`127.0.0.1`/`::1` check) and stashes the policy in the request context; `originAllowed(r)` reads it back for the cross-origin write gate (config, config/raw, state/recent-actions, open-file) — context rather than a `Server` field so TabFactory tabs and the package-level config/state handlers need no plumbing; no policy in context (tests on `srv.Mux`) = loopback only. `NewHostPolicy` validates `--allowed-host` entries (bare hostname or IP; rejects empty, wildcards, ports, URLs) and normalizes (lowercase, IPv6 brackets, trailing dot); matching is exact. All methods nil-safe. The one rejected-Host log line is once per process (a rebinding page can retry in a loop).

## frontend/

Svelte 5 SPA (Vite + TypeScript + pnpm)

- **`src/AppShell.svelte`** — Tab-switch host. Must be called during component init (creates an $effect; tests wrap in `$effect.root`). App curries the shared opId/gate via a local `opSync()` helper. Tests: op-sync.svelte.test.ts — the three review races (failed-fetch retry on next op-id, mid-fetch op-id → exactly one more refresh, gate-held staleness retention) are the core suite.
- **`revision-navigator.svelte.ts`** — createRevisionNavigator(): diff/files/description loaders + revGen batch-fetch orchestration + navigateCached (double-rAF paint-first deferral) / navigateDeferred (50ms debounce coalesce). cancel() clears both timers + bumps revGen — switchToLogView/onDestroy/handleRevsetSubmit all call it. **Sole owner of `loadedTarget`/`diffContentKey`/`diff.value` — every diff load goes through `loadDiffAndFiles`/`applyCacheHit`/`loadMulti` so the triple advances atomically.** App calling `diff.load()` directly desyncs DiffPanel's `contentMatchesTarget` (the v1.19→1.20 memo-poisoning class). Scheduling was previously inline in App.svelte's selectRevision; moved here so the "rapid j/k only renders destination" contract is testable with fake timers.

- **`modes.svelte.ts`** — Rebase/squash/split/megamerge mode state factories sharing one `ModeBase` contract: `kind` ('rebase'|'squash'|'split'|'megamerge' discriminant for kind-keyed dispatch tables), `sources` (revisions the op acts on — split exposes `[revision]`; its `revision` field stays as an alias; megamerge exposes `[target]`), `hasDestination` (does the j/k cursor pick a destination? rebase/squash/megamerge yes, split no — drives target badges, the `/` typed-destination input, and whether j/k exists in the mode), and `diffFollows` (the per-mode nav semantic: rebase=true destination-preview, squash/split/megamerge=false frozen-on-source). App derives `diffFrozen` from diffFollows so mouse onselect + the multi-check $effect read one source instead of each spelling out `squash.active || split.active`; consumers (RevisionGraph badges, StatusBar, App's executeInlineMode lookup) read the shared fields and only dispatch on `kind` for label text. `inlineMode` stays for binary gates; `diffFrozen` is the answer `inlineMode` can't give. SplitMode.review distinguishes 'v' (review: accepted/rejected labels) from 's' (split: stays/moves labels) — same jj split underneath. SquashMode.descMode ('destination'|'source'|'combine', cycled by `m`, reset on enter; issue #22) chooses which description the squashed commit keeps — the backend composes it into `-m`; default 'destination' = jj's `--use-destination-message`. **MegamergeMode** (jjui's `M`: edit a commit's parent set in place) is the one MULTI-destination mode — its optional `destinationIds` field (commit_ids of the chosen parent set, since `commit.parent_ids` ARE commit_ids) makes RevisionGraph render a target badge on EVERY parent row instead of a single cursor-row target; Space (handled in App — needs the cursor row's commit_id) toggles membership via `toggle()` (guards the target's own commit_id), Enter runs ONE `jj rebase -r target -d p1 -d p2 …`, `initialParentIds` is the no-op-exit baseline. `handleKey` is a no-op (all keys handled in App).
- **`slide.ts`** — computeSlide(): Shift+J/K single-step commit reorder along a linear graph segment. Targets the topological parent/child edge (not the visually adjacent row); merge/fork points and immutable neighbors return `{ok: false, reason}` instead of a rebase target.
- **`config.svelte.ts`** — Reactive config singleton — primary storage os.UserConfigDir()/lightjj/config.json, localStorage as write-through cache. **Dirty-key saves**: public setters go through `setKey` which marks the key dirty; the debounced flush POSTs ONLY dirty keys (backend merges per-key) — never the full snapshot, so two lightjj instances sharing one config.json can't revert each other's changes (lost-update fix). `applyPartial()` (hydration, ConfigModal live-apply, storage-event sync) writes state WITHOUT marking dirty → no echo POST. `recentActions` getter/setter is a back-compat delegation to recent-actions.svelte.ts (machine state, not config — never POSTed to /api/config). `fontSize` getter clamps to `FONT_SIZE_MIN..MAX` with `Number()`+`isFinite` so all read sites (CSS var, palette label, ±1 arithmetic) see a sane value regardless of load path.

Exposes `recentActionsStore` (whole-map accessor used by config.svelte.ts's back-compat delegation) + the `recentActions(namespace)` factory. Persistence is best-effort: every api call is try/caught so partially-mocked api modules in component tests (and a down backend) degrade to in-memory-only.
- **`annotations.svelte.ts`** — Per-line review comment store for agent workflows. createAnnotationStore() + reanchor() + exportMarkdown/JSON. Server-side storage via /api/annotations (workspace tabs share). `list: Annotation[]` (wire truth) → `placed: PlacedReview[]` $derived projection; `byId(id)` recovers the wire object from a projection id (call sites should use it instead of `list.find`). Mutations route through review-mutations.svelte.ts `run()` — optimistic apply, rollback shapes documented in-file (add/setReviewed(true) = surgical by-id; update/remove/clear = gen-guarded snapshot); failures rethrow for DiffPanel's catch sites. `isReviewedMarker` is a wire-shape wrapper over review.ts `isReviewedReview` (single sentinel definition). Re-anchor via diffRange delta + ±5 content scan (new-side only — old-side pinned to pre-image). NO negative caching of empty changeIds — agents POST annotations out-of-band (other tabs, the agent CLI), so a "known empty" memo would hide them permanently; load() always hits the server.
